# ADR-002: 分级上下文压缩策略

**状态**: 已接受
**日期**: 2026-06-03

## 上下文

当前 context.ts 的压缩策略是简单粗暴的：
1. 先尝试压缩工具结果（截断长文本）
2. 不够就直接截断消息列表

这在短对话中工作正常，但在长对话/复杂工作流中会导致问题：
- 丢失关键的推理过程（模型失去了之前决策的上下文）
- 一次性大幅截断导致对话连贯性断裂
- 无法区分重要和不重要的消息

通过研究 forge 的 TieredCompact 策略，我们发现渐进式分级压缩可以更好地保留关键信息。

## 决策

引入 **TieredCompact 三阶段渐进压缩**策略：

**Phase 1（轻度, ≥75% 预算）：**
- 删除所有 guardrails nudge 消息（纠错消息，一次性使用）
- 截断超过 2000 字符的工具结果为摘要
- 保留所有工具调用、推理文本、用户输入

**Phase 2（中度, ≥85% 预算）：**
- 完全移除工具执行结果
- 保留工具调用本身（让模型知道调用过什么工具、传了什么参数）
- 保留推理文本和用户输入

**Phase 3（重度, ≥95% 预算）：**
- 只保留系统提示 + 用户原始输入 + 最近 2 轮工具调用
- 移除所有中间推理和文本响应

**始终保留：**
- 系统提示（第一条消息）
- 用户原始输入（不可压缩）
- 最近的 `keepRecent`（默认 2）轮迭代

### 考虑过的替代方案

**方案 A：只用摘要压缩**
- 用 LLM 对历史消息生成摘要，用摘要替代原始消息
- 优点：保留语义，信息损失最小
- 缺点：需要额外 LLM 调用（成本和延迟），SDK 模式下可能没有可用的 LLM

**方案 B：滑动窗口**
- 固定保留最近 N 条消息，丢弃更早的
- 优点：实现简单
- 缺点：丢失所有早期上下文，可能导致模型无法完成早期设定的任务

**选择分级压缩的原因：**
- 无额外 LLM 调用成本
- 渐进式压缩给模型更多有用上下文
- 可以根据消息类型区分优先级
- 在 forge 项目中经过充分验证

## 后果

**正面：**
- 长对话中保留更多关键信息
- 渐进式压缩避免对话连贯性突然断裂
- 在 forge 的 26 场景评估中证明有效

**负面：**
- 实现比简单截断复杂
- 三阶段阈值需要根据实际使用调优
- 需要额外的 token 估算逻辑（无法使用精确 tokenizer 时需要近似）
